# 仕入請求・買掛管理

2026-10-02追加。D0の同期契約を保持し、既存の発注・入荷に仕入先、原請求、買掛、物品返品、減額、支払・返金の記録を接続する。共有要求・応答は `@regi/core/finance`、追加DBは `008_purchase_finance`。000〜007のmigrationファイルとchecksumは変更しない。

## 画面と権限

| URL                       | 操作                                                                             |
| ------------------------- | -------------------------------------------------------------------------------- |
| `/purchases/orders`       | 発注・入荷。仕入先マスターを選択し、既存の発行済み発注には理由付き対応記録を追加 |
| `/purchases/suppliers`    | 仕入先の登録・編集・停止                                                         |
| `/purchases/invoices`     | 原請求の検索・下書き作成                                                         |
| `/purchases/invoices/:id` | 明細・税額・原資料・確定・相手方確認・支払・減額・返金・訂正・出力               |
| `/purchases/payables`     | 条件全体の買掛残高・期日・履歴時点・CSV                                          |
| `/purchases/returns`      | 入荷からの物品返品と逆記録                                                       |

各画面は `storeId` を保持し、直接アクセス・再読込・履歴移動に対応する。法人・担当者・店舗の変更時は古い応答を破棄する。所属外店舗のURLでは書込みを止める。

管理者・本部は金融操作を行える。店長は担当店舗の閲覧、通常の下書き編集、物品返品を行える。買掛確定・減額・支払・返金・訂正は管理者・本部に限る。レジ担当には金融API、原資料、金融帳票を公開しない。全13表にFORCE RLSを設定し、未分類DB接続も拒否する。changesへ配信する金融情報はID・状態・版に限定し、レジ担当への配信はページ分割前に除外する。

## 原請求と確定

原請求番号、原請求日、原書類受領日、実取引日、相手方、元の税額と資料を別々に記録する。未入力の原日付・金額を今日や0円で補わない。下書き保存では買掛を計上しない。

確定時に原明細・税額・仕入先のスナップショットとSHAを保存し、後のマスター変更を反映しない。原請求の重複は同一法人・仕入先・原識別・版で拒否する。番号のない書類にも識別と証拠を必要とする。

買手作成の仕入明細は、債務の確定と相手方確認を分ける。確認相手・実際の日時・方法・用途が `supplier-confirmation` の資料を、確定済み明細のSHAへ対応付ける。入力済みの確認記録であり、REGIが相手方の署名や身元を認証したという意味ではない。

確定取消は元明細を残し、理由・実際の取消日時・逆の債務記録を追加する。訂正は取消済み原請求を前身として別下書きにする。同時に1つの有効な訂正下書きだけを認め、原資料は訂正版へ再添付する。旧版と新版は画面で相互に開ける。

## 金額・税額と残高

円は文字列とBigIntで扱う。入力は整数円最大30桁、最大500明細、明細数量は1〜10,000。集計をPostgreSQLへ記録できる範囲も事前検査する。入力欄の不正な数量・税率・金額を0や1へ置換しない。

税額は原書類単位・税率区分ごとに一度だけ丸める。原書類記載額と計算額を区別し、差額を認める場合は対象プレビューSHA・理由・証拠を管理者・本部が確認する。軽減対象は明示的な分類であり、8%という数値だけから推測しない。税額0と税額の未確定を区別する。

入荷明細の請求割当可能数と物品返品可能数を別管理する。物品返品は在庫を動かし、原請求を自動減額しない。仕入先が承認した減額は、元の明細数量または元の税抜額・税額・税込額の残りから記録する。減額には承認日時・理由・専用資料を必要とする。

残高は確定債務＋各取消−減額−支払＋返金受領と逆記録から計算する。未払額と返金待ち額を分け、支払超過・返金待ち超過を拒否する。支払・返金は外部で実施済みの取引の記録であり、銀行振込の実行機能ではない。銀行振込には外部参照、その他の方法には説明を必要とする。

実際の日時は日本時間で秒まで入力でき、未来の事実、入荷前の物品返品、元事実より前の取消を拒否する。記録日時はDB側に保存し、遅れて入力した取引を過去に観測した残高へ混ぜない。

## 通信断・原資料・出力

金額操作・資料添付・出力は同じ操作IDと同じ入力を再送できる。応答が不明な間は新規実行へ切り替えず、同じ操作を再確認する。画面移動中も元の店舗と操作を示し、法人・担当者の変更後に別の資格で実行しない。資料の内容と認証情報は永続のブラウザー保存へ書かない。再読込後は同じ操作者・店舗で保存結果を照会し、保存済みなら原記録を再取得する。404や通信失敗では不明状態を保持し、未保存の証明とは扱わない。未確認の資料を同IDで再送する場合は元ファイルを再選択する。

原資料はPDF・PNG・JPEG、1ファイル10MiB、1請求20件。MIMEと実バイトを検査し、非公開オブジェクトとサイズ・SHAを対応付ける。用途に合う資料だけを各操作で選択する。取得時にも権限・店舗・サイズ・SHAを検査し、欠落・破損はエラーとして表示する。確定処理も必要な原ファイルの存在と一致を確認する。

PDF、買掛CSV、支払CSV、請求と資料の一括出力は要求時点の `asOf` と観測時点、原スナップショットを固定する。ページ分割しても同じ観測内容を使う。表示時点から内容が変わった可変リストのカーソルは再取得を求める。

一括出力には原ファイル、管理用PDF、固定明細、記録CSV、ファイル名・サイズ・SHAのmanifestを含める。非圧縮64MiB超は一部を黙って省かず拒否し、個別の原ファイル取得を案内する。PDFは買手作成明細の相手方確認待ち、原資料の管理用写し、軽減対象を明示する。

## 保存期間と受入

契約中の保管、終了後30日の閲覧・出力、終了から90日以上経過した法人への明示的保守削除は既存契約仕様を保持する。削除は13表を含む依存順と全オブジェクト版を扱い、FORCE RLSと不変トリガーを復帰する。顧客の長期保管に必要な原資料・出力は終了前に取得し、REGIで法定保管期間全体を保証した扱いにしない。

バックアップのライフサイクルは現行35日＋非現行35日で、単純な上書きの例で約70日残る。複製未成功では延長する場合がある。今回のVMからAWS配備・S3操作・実消去確認はしていない。

検証は実PostgreSQL・実HTTP・Chrome、空DB/既存007移行、並行接続、権限と破損注入、応答切断、実ファイルのSHA照合を使う。合成試験を実顧客の有償実績や審査承認と扱わない。最終結果は [実装状況](../implementation-status.md) に記録する。正式提出資料はユーザー指示により保留中。
